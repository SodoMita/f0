What changed

Loading indicator — a spinning ring of dots

One idiom everywhere. In the HUD: 12 SVG dots with a fading trail, rotated by a CSS steps(12) animation, labelled connecting / loading model / building thread. On the canvas: the same ring drawn once into a texture and spun via rotation.z on every board card and thread node that has no poster yet — so it stays crisp at any DPR or zoom and costs nothing per frame. setLoading(reason, on) is reference-counted, so one finished job can't hide another job's ring.

Overlapping models in the viewer — fixed

Viewer.load() cleared the scene and then awaited blob.arrayBuffer() + LoadAssetContainerAsync. A second navigation during that await cleared an already-null container, and both parses then called addAllToScene() — two (or six) models stacked in the single-model view, with every superseded container leaked. Now every load takes a token: a parse that returns stale disposes its own container; clear() bumps the token (cancelling in-flight loads) and sweeps any non-helper mesh / transform node / camera out of the scene; and main.ts holds a matching navigation ticket so a late download can't paint into a view you already left.
